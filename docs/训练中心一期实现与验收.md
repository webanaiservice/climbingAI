# 训练中心一期实现与验收

入口：`/dashboard/training`。已接入 Climbing AI 现有登录、岩馆工作区、侧边导航和总览。此版本是数据库与视频服务驱动的功能实现，页面没有内置运动员或模拟成绩。

## 本期功能

- 运动员档案：姓名或训练昵称、出生日期、训练起始日期、教练、组别、目标、备注；支持编辑、归档与恢复。
- 成长与体能：按实际日期追加身高、体重、臂展、体能测试方法和结果，保留历史。
- 固定线路：星星道 / 飞鸟道按馆内安装版本建档，记录标准来源；不自动将未经核实的安装标成某国际标准。
- 训练日志：日期、内容、目标、时长、主观疲劳、身体感受；攀爬尝试可关联训练课。
- 攀爬记录：全程 / 分段、A/B 道、成功 / 脱落 / 主动结束 / 待确认，毫秒级存储成绩，明确电子计时 / 视频估时 / 秒表来源。
- 视频：MP4、MOV、M4V、WebM，单次 200 MB、0.3–180 秒。保存原文件和无音轨的 H.264 回放文件；登录后通过鉴权接口播放，支持 Range 分段请求、慢放、时间点标记及本人同线路同类型视频对照。
- AI：持久化分析队列，按指定区间抽取最多 40 张带原视频时间戳的画面；结合视频当时的年龄、训练年限、最近测量、体能测试、关联训练课及之前的同线路成绩。保存请求快照、模型、报告版本及失败状态。分析按钮旁说明本次外部处理范围，点击提交时后台记录操作人和同意事件。
- 教练复核：保留 AI 原稿和每次教练意见，仅在最新意见为“确认”后才允许从报告生成任务。人工任务无需先调用 AI。
- 任务复测：待安排 → 练习中 → 待复测 → 已有改善 / 尚未改善；完成复测必须关联同一运动员的攀爬记录及结论。
- 成长报告：按运动员、线路版本、全程和计时来源筛选；计算最佳、中位数、完成率；失败不算零秒，待确认不进入完成率分母。

## 集成与运行

数据库新增 9 个训练模型。迁移 `20260925090000_athlete_training` 已在本机数据库执行；生产部署仍需运行正常的迁移流程。训练视频独立于摄像头临时证据，不受摄像头过期清理影响。

API 模块位于 `apps/api/src/training/`，页面组件位于 `apps/web/src/features/training/`。沿用组织隔离与现有 L1/L2 员工账号；本期没有新增家长账号或更细的教练分组授权。两个员工角色均具备训练模块读写与复核能力。

API 环境配置：

```dotenv
DEROUTER_API_KEY=服务端密钥
DEROUTER_OPENAI_BASE=https://api-direct.derouter.ai/openai/v1
TRAINING_AI_MODEL=gpt-6-astra
TRAINING_FFMPEG_PATH=ffmpeg
```

GPT 模型使用 OpenAI 兼容的 `chat/completions` 图像输入及 JSON 输出；Opus 使用 Anthropic `messages` 图像输入与工具结构化输出。密钥仅留在服务端，不发送到浏览器。Docker API 镜像已包含 FFmpeg；生产 Compose 已补充训练模型和 FFmpeg 参数。对象存储沿用现有 MinIO 配置，必须使用持久卷。

现有 Next.js 代理超时调整为 300 秒，转发请求体上限调整为 210 MiB（文件仍限制为 200 MiB），兼容上传与转码。部署端如额外使用反向代理，应允许 200 MB 请求体和足够上传时间。无模型密钥时仍可使用档案、日志、播放、人工标记、人工任务和报告统计；页面明确显示 AI 待配置。

## 一期边界

这不是经过攀岩专项验证的自动教练。当前实现通过视频抽样给出可复核的观察与练习思路，没有训练专用姿态模型，也不会输出测力、精确重心、自动电子成绩或伤病诊断。

历史视频并排比较目前由教练人工选择与对齐，AI 本次只读取当前选定视频的抽样图像；历史对照数据只包含文字记录，不声称已经分析过历史视频。线路模板暂存名称和版本，尚未录入标准岩点坐标或建立自动岩点匹配。

近期工作区视图最多读取 500 位运动员、每人 30 条测量、200 次训练课、400 次攀爬、400 项任务；尝试详情显示最近 10 次 AI 分析。数据库保留全部记录。大量使用前需补分页、历史检索与导出。

分析队列在 API 内执行，每实例一次处理一个任务；多实例通过数据库原子更新抢占，运行超过 10 分钟标记失败。更大规模部署需拆分独立媒体 Worker、并发配额和监控。

## 上传与模型选择修复（2026-09-25）

用户反馈的上传卡住已定位为 Next.js 15.5 转发层默认 10 MiB 请求体截断。浏览器与 API 虽允许 200 MiB，但大视频进入转发层后被截断，API 最终抛出 `ERR_STREAM_PREMATURE_CLOSE`。已调整 `middlewareClientMaxBodySize`，并在前端增加真实传输百分比、上传后转码状态、取消、超时与明确成功消息，重试可重新选择同一个文件。

复盘界面新增三个选项：Claude Opus 5.5 (`claude-opus-5-5`)、GPT-6 Astra (`gpt-6-astra`)、GPT-6 Sol (`gpt-6-sol`)。后端白名单校验并将所选模型存入每次分析记录，历史报告显示实际使用模型。密钥和两个 endpoint 复用原 AI 岩馆的配置，不向浏览器暴露密钥。

Opus 使用 Anthropic `/v1/messages` 图像块与工具结构化输出，GPT 使用 OpenAI 兼容 `/chat/completions`。该服务的 GPT JSON 模式要求用户消息包含 JSON 字样，现已在真正的用户输入块中加入此要求并用回归测试保护。认证、限流、连接和格式失败会分别显示可操作的错误提示。

已通过网页实际使用的 `/backend` 入口上传 74.6 MiB 合成视频：上传、转码、持久保存约 2.5 秒，随后 Range 回放返回 206。三个模型均完成真实图像请求及报告解析。全量 API 测试 166 项通过、Web 测试 45 项通过；原有 9 项按条件跳过。前后端构建与本次修改的 ESLint 均通过。

本机 FFmpeg 放在 `.local/bin/ffmpeg`，本机 `.env` 保存其绝对路径与训练存储路径，均不纳入 Git。备份训练数据需同时备份 PostgreSQL 与 `.local/training-videos`；服务器部署继续使用既有 MinIO 持久卷。

## 完整队列验收补充（2026-09-26）

新增真实 PostgreSQL 回归测试 `training-lock.integration.spec.ts`，验证加锁可执行、并发事务无法取得同一锁、提交后锁释放。执行 `DATABASE_INTEGRATION=true` 的专项测试通过。

独立测试工作区已实际完成：通过网页代理读取持久视频 → 提交 GPT-6 Astra 分析 → 抽取合成视频画面 → 真实模型响应 → 报告校验 → 数据库状态 READY。测试素材没有人物，报告未生成动作问题（findings 为空）。验收工作区与合成视频已清理，用户原有运动员档案和攀爬记录保留。
